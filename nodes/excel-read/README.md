# Excel Read

Универсальное извлечение `.xls`, `.xlsx`, `.xlsm` без бизнес-интерпретации,
выполнения формул, макросов и внешних связей. Пустая ячейка отсутствует в
выгрузке; она не становится нулём. Ошибка чтения завершает ноду ошибкой без
публикации частичной выгрузки.

Вход `file` — материализованный file-объект фабрики. Вход `attachment` может
содержать такой же объект или совместимый старый объект с `content_base64`.
Base64 ограничивается до декодирования. При заданном SHA256 проверяется хеш.
Если attachment_id отсутствует, идентификатором служит SHA256.

Для чтения ZIP из IMAP передайте пакет на `file`, а метаданные конкретного
вложения из `messages[].attachments[]` на `attachment`. Из архива потоково
читается ровно указанная часть; пути на диск не распаковываются. Поля
`filename`, `archive_entry`, `sha256`, `attachment_id` сохраняют происхождение.
Вход `archive_entry` позволяет явно переопределить путь части.

Полный результат находится в `cells_file` — JSONL, версия 1.0. Каждая строка
имеет `record_type`: `workbook`, `sheet`, `cell`, `merged_range`, `issue`,
`number_format`, `cell_style`. Координаты row/column начинаются с 1.

OOXML читается потоково с запретом DTD и внешних XML-сущностей. `raw_value`
сохраняет исходное содержимое `<v>`, `value` раскрывает строковые таблицы и
boolean. Числа остаются точными десятичными строками, включая ноль; даты не
пересчитываются по номеру формата. Система дат и стили передаются отдельно.
`formula` сохраняет выражение, `formula_attributes` — сведения об общих и
массивных формулах. Зависимая общая формула не угадывается: её атрибуты
ссылаются на исходную формулу, добавляется предупреждение.

Для формулы без кэша: `value=null`, `cached_value=null`, `cache_status=unknown`
и предупреждение `formula_without_cached_value`. Существующий кэш не считается
пересчитанным или гарантированно актуальным. Для пустой строковой формулы с
сохранённым пустым кэшем значение — пустая строка.

Для XLS библиотека xlrd возвращает исходные BIFF-типы и сохранённые значения,
объединения, форматы и числовые даты без перевода в бизнес-даты. Выражения
формул и происхождение их кэша недоступны: выдаётся глобальное предупреждение
`xls_formula_expressions_unavailable`, у ячеек
`cache_status=formula_provenance_unavailable`. `formula=null` здесь не доказывает
отсутствия формулы. Перед использованием XLS в вычислениях учитывайте это
ограничение или сохраняйте исходник в XLSX с кэшами на стороне источника.

Лимиты: входной файл, сумма распакованных OOXML-частей, число ZIP-записей,
число ячеек и общий размер JSONL. XLS читается по одному листу. `cells` — только
просмотр (до `preview_cells` и 64 КиБ), `warnings` — первые 50; полные данные и
предупреждения остаются в файле. В Unix-runner дополнительно действует
`max_memory_bytes` (по умолчанию 512 МБ) через RLIMIT_AS.
`memory_limit_enforced` сообщает, применён ли системный лимит. На Windows
этот механизм недоступен: остаются лимиты размеров и числа ячеек.

Как и для IMAP, Workflow Cloud должен предоставить верхнеуровневый файловый
контракт `output_files.cells_file.file`, а потребитель — получить файл через
`input_files.file`. Наличие локального `tmp_path` не подтверждает передачу
между разными runner-контейнерами.
